
# Task 3 – Kakuro Constraint Satisfaction Problem

## 1. Overview

This task implements a Kakuro puzzle solver using Constraint Satisfaction
Problem (CSP) techniques.

The implementation includes:

- CSP modeling: Variables, Domains, and Constraints.
- Constraint Processing and Generalized Arc Consistency (GAC).
- Constraint Propagation.
- Backtracking Search.
- MRV (Minimum Remaining Values).
- Degree Heuristic.
- LCV (Least Constraining Value).
- Pygame graphical user interface.
- Experimental evaluation and result visualization.

The project contains two puzzle configurations:

1. Reference 9x9: the complex Kakuro puzzle provided in the assignment.
2. Backtracking Demo: a smaller puzzle designed to demonstrate search,
   contradiction detection, and backtracking.

## 2. CSP Formulation

### 2.1 Variables

Each white cell is represented by a variable:

    X[r,c]

The reference board contains 48 white cells and therefore 48 variables.

### 2.2 Domains

Every unassigned variable initially has the domain:

    D(X[r,c]) = {1, 2, 3, 4, 5, 6, 7, 8, 9}

### 2.3 Constraints

Each horizontal (Across) and vertical (Down) run has two constraints:

1. The sum of all digits in the run must equal its clue.
2. No digit may appear more than once in the same run.

The reference puzzle contains:

- 14 Across runs.
- 14 Down runs.

A white cell belongs to exactly one Across run and one Down run.

## 3. Algorithms and Techniques

### 3.1 Constraint Processing

Valid digit combinations are generated by considering the run length
and target sum.

The solver checks whether each candidate assignment satisfies:

- The target sum.
- The all-different constraint.
- The current domains of all variables.

### 3.2 Constraint Propagation

The implementation uses Generalized Arc Consistency (GAC) at the run
level.

A domain value is removed if it does not participate in any valid
assignment for its corresponding run.

When a domain changes, the intersecting constraint is added back to
the propagation queue.

The process continues until:

- No more domain values can be removed; or
- A contradiction is detected.

### 3.3 Backtracking Search

When propagation does not produce a complete assignment, the solver
uses Backtracking Search.

The search combines:

- MRV: select the variable with the smallest remaining domain.
- Degree Heuristic: break MRV ties by selecting the variable with
  the most unassigned neighbors.
- LCV: prioritize values that eliminate fewer neighboring candidates.
- Forward propagation: enforce constraints after every assignment.

The solver records decisions, domain pruning, contradictions,
backtracks, and solution events.

### 9.1 Result Interpretation

Solve rate measures the percentage of runs that produce a complete
assignment.

Consistency rate measures the percentage of propagation runs that
do not detect a contradiction.

These metrics must not be interpreted as equivalent.

A propagation run can remain consistent while still containing
unassigned variables.

## 12. Implementation Notes and Limitations

The reference puzzle is solved entirely by Constraint Propagation
in the recorded experiment. Therefore, its search node and
backtrack counts are zero.

The Backtracking Demo is used to demonstrate the actual search
process when propagation alone does not produce a complete
assignment.

The current LCV heuristic estimates impact using neighboring
variables that share an all-different constraint. It does not
calculate the complete global impact of every candidate value.

The benchmark results describe the implemented puzzles and
configuration. They do not establish that the reference puzzle
has a unique mathematical solution.
